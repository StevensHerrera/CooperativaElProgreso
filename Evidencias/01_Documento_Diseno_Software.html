Cooperativa Financiera El Progreso

Sistema de gestión de asociados, movimientos y reportes administrativos
Versión 1.0 | 2026

1. Introducción

Cooperativa El Progreso es una aplicación de consola diseñada para apoyar la operación de una cooperativa financiera. Permite al cajero registrar y consultar asociados, registrar consignaciones y retiros, consultar movimientos y convertir el saldo a dólares usando la TRM oficial. También ofrece al administrador reportes para analizar la actividad de la cooperativa.

El sistema representa una cuenta de ahorro por asociado. El saldo no se almacena como un valor editable: se calcula sumando los movimientos aceptados. Esta decisión evita inconsistencias y conserva el historial de operaciones.

2. Alcance

  • Gestión de asociados: registrar, consultar, actualizar y eliminar bajo las reglas definidas.
  • Gestión de movimientos: consignaciones, retiros, comisiones y validación de saldo.
  • Consulta de TRM mediante un servicio externo oficial.
  • Seis reportes administrativos.
  • Interfaz de consola para los roles de cajero y administrador.
Alcance actual: la aplicación utiliza almacenamiento en memoria y no incluye una interfaz web ni una base de datos persistente. El modelo de base de datos incluido en esta evidencia es una propuesta para una versión futura.

4. Requisitos no funcionales

  • Disponibilidad: un fallo de la API de TRM no debe cerrar la aplicación.
  • Mantenibilidad: las responsabilidades se separan por capas.
  • Pruebas: la lógica principal se verifica con pruebas unitarias xUnit.
  • Integridad: los movimientos aceptados son de solo adición y no se borran.
  • Tecnología: C# 14 y .NET 10.

5. Arquitectura del software

Se utiliza una arquitectura por capas dentro de un proyecto ejecutable:

CapaResponsabilidad
UIPresenta menús de cajero y administrador y recoge entradas del usuario.
ServicesContiene las reglas de negocio y coordina repositorios y servicios externos.
RepositoriesAbstrae el acceso al almacenamiento de asociados y movimientos.
DataProporciona el almacenamiento en memoria compartido.
InfrastructureIntegra la API externa de TRM.
ModelsRepresenta entidades, resultados y DTO de reportes.

El punto de composición es Program.cs, donde se crean las dependencias y se inyectan en los servicios y menús.

7. Justificación técnica

  • Las interfaces reducen el acoplamiento y permiten reemplazar implementaciones.
  • El saldo derivado evita que se pueda editar manualmente.
  • OperationResult<T> comunica rechazos esperados sin usar excepciones para cada regla de negocio.
  • La API está aislada en infraestructura porque es una integración externa, no una regla del negocio.
  • Las pruebas pueden usar FakeExchangeRateService y no dependen de Internet.

8. Conclusión

El diseño prioriza separación de responsabilidades, trazabilidad de movimientos y tolerancia ante fallos externos. La propuesta permite evolucionar desde el almacenamiento en memoria hacia una base de datos sin modificar la lógica de negocio principal.
